# MMO RPG — 자바 에디션 (Fabric 모드)

베드락 애드온 **MMO RPG 시스템** (v2.27.0) 을 마인크래프트 **자바 에디션 26.3 (Fabric)** 으로 옮기는 모드입니다 (1.21.1 판은 따로 보관 — 아래 설치).
밸런스 수치와 공식은 애드온에서 그대로 가져온 규칙 코어 (`core/`) 를 씁니다 — 애드온 JS 와 같은 입력 28,530개에서 같은 값이 나오는 것을 매 빌드마다 확인합니다.

2단계에서 1단계의 임시 표현 (바닐라 파티클 · 평면 무기 그림) 을 모두 애드온 그림 · 모델로 바꿨습니다. 남은 차이:
- 이펙트는 서버가 보내므로 누른 뒤 1~2틱 (0.05~0.1초) 늦게 보일 수 있음 (서버가 멀수록 더)
- 빛 알갱이 자리는 쉬는 자세 기준 (휘두르는 동안의 팔 움직임은 따라가지 않음 — 알갱이는 세계에 남아 떠오르므로 차이가 작음)
- 화면 흔들림 세기는 어림값 (세기 1 ≈ 10°, 베드락은 수치를 밝히지 않음)

3단계 (스킬 · 룬) 의 자바 판 차이:
- 룬 칸을 고르기만 해도 쓰기 (애드온의 터치 조작) 는 자바에 터치가 없어 기본 꺼짐 — `/runequick on` 으로 켬
- 하늘빛은 베드락 `/fog` 대신 클라이언트가 안개 거리 · 색을 바꿈 (모드가 없는 클라이언트는 보이지 않음)

4단계 (갑옷 · 상점 · NPC · 퀘스트) 의 자바 판 차이:
- 창은 베드락 리소스 팩 UI 대신 모드의 화면 (같은 그림 · 배치) — 모드가 없는 클라이언트에서는 창이 열리지 않음
- NPC 몸은 마네킹 (자바에는 베드락 NPC 엔티티가 없음) — 스킨은 설정 창에서 플레이어 이름으로

5단계 (몬스터 · 보스 · 제단 · 세계수) 의 자바 판 차이:
- 몬스터 · 보스는 애드온 엔티티 정의 (행동 팩 · 리소스 팩) 를 자바 엔티티로 옮겨 그림 — 모델 · 텍스처 · 동작 · 빛나는 칸 · 렌더 컨트롤러 그대로. 모드가 없는 클라이언트에서는 보이지 않음
- 플레이어가 받는 피해의 방어구 계산을 베드락 식으로 (방어 1 = 4% 감소, 최대 20 = 80%) — 자바 바닐라 식 (갑옷 강인함) 대신. 애드온 보스 · 몬스터 수치가 이 식에 맞춰져 있음
- 보스 체력: 자바 최대 체력 상한 (1,024) 을 1,000,000 으로 올림 (수르트 90,000)
- 두 줄 이름표 (이름 + 체력 막대) 는 몬스터에 태운 글자 엔티티 (자바 이름표는 한 줄), 보스 안개 (`/fog`) 는 모드 클라이언트의 안개
- 긴 제목 · 부제목 (보스 처치 · 패턴 안내) 은 화면 너비에 맞게 줄여 그림 (자바 제목은 글자가 커서 양옆이 잘렸음)
- 3단계 스킬 · 룬 파티클 중 움직임 정의가 빈 11종 (오딘의 까마귀 · 활 빛줄기 · 궁니르 창 등) 이 멈춰 있던 것을 고침 (처음 빠르기로 움직임)
- 플레이어에게 준 밀치기 · 띄우기 · 끌어당기기 (보스 패턴 · 그람 용익 강하의 솟구침 등) 가 서버에만 있고 화면의 몸은 움직이지 않던 것을 고침 (속도를 그 사람에게 바로 보냄)

6단계 (탈것 · 엔더 상자 · 결투 · 스탯 창 아랫줄) 의 자바 판 차이:
- 탈것은 애드온의 1종 (다이어울프) 에서 여러 종으로 (사용자 요청 — 탈것 아이템 · 고르기 창). 처음 탈것 · 조작 · 연출 · 막기 규칙은 애드온 그대로
- 탄 사람 높이: 베드락 자리 + 0.13칸 (자바 플레이어는 발 + 0.6 이 붙는 점 — 엉덩이가 안장 위에 오게, `seatLift` 로 탈것마다 바꿀 수 있음)
- 엔더 상자 창은 애드온의 상자 모양 창 (칸을 눌러 옮김 · 옮기는 양 단추) 대신 바닐라 상자 창 (베드락은 스크립트로 바닐라 상자 창을 열 수 없었음 — 같은 27칸)
- 결투 신청 창은 다른 창이 열려 있으면 닫힐 때까지 기다렸다 띄움 (베드락의 "바쁨" 다시 시도와 같음)
- 탈것은 청크에 저장하지 않음 (탄 채로 나가면 바닐라처럼 플레이어와 함께 저장 → 다시 들어오면 탄 채로)

애드온 v2.27.0 의 기능을 모두 옮겼습니다 (위의 자바 판 차이 말고는 같음). 계획 · 대응표는 `PLAN.md`.

## 설치

1. [Fabric Loader](https://fabricmc.net/use/) (0.19.5 이상) 를 마인크래프트 **26.3** 에 설치
2. [Fabric API](https://modrinth.com/mod/fabric-api) (26.3 용, 0.162.0 이상) 와 이 모드 jar 를 `mods` 폴더에
3. 모드 jar: 이 저장소의 **Releases → latest** (main 에 올릴 때마다 모든 시험을 통과하면 자동으로 새로 만들어짐)

마인크래프트 **1.21.1** 용 (1단계까지, 더 고치지 않음): **Releases → release-mc-1.21.1** (`mc-1.21.1` 브랜치, Fabric API 0.116.x+1.21.1).

서버에서 쓰려면 서버와 클라이언트 모두에 넣어야 합니다 (창 · 갑옷 입은 모습 · 체력 바 · 길 안내 · 몬스터 · 보스 · 탈것은 클라이언트의 모드가 그림).

## 새 탈것 더하기

탈것은 데이터로 정합니다 (코드를 고치지 않음):

1. 애드온 행동 팩에 탈것 엔티티 (`RPG_BP/entities/rpg_mounts/<이름>.json` — `minecraft:rideable` 자리 · `movement` 빠르기 · `horse.jump_strength` 뛰는 힘 · `variable_max_auto_step` 오르는 높이 · `collision_box` · 피해 면역, 다이어울프와 같은 모양) 과 리소스 팩 (모델 · 동작 · 렌더 컨트롤러 `render_controllers/rpg_mounts/` · 텍스처) 을 넣음
2. `src/main/resources/mmorpg/mounts.json` 의 `mounts` 에 한 항목: `name` (이름) · `entity` (엔티티 ID) · `item` (탈것 아이템 ID, `rpg:mount_<키>`) · `starter` (처음부터 가짐) · `color` (연출 색) · `particle` (흩날리는 파티클) · `portrait` (아이템 그림 바탕) · `sounds` (부를 때 · 사라질 때) · `desc` (아이템 설명) · `seatLift` (탄 사람 높이 보정, 없으면 0.13)
3. `python3 tools/bedrock_entities.py <애드온 폴더>` (엔티티 수치 · 모델 · 텍스처) 와 `python3 tools/mount_items.py` (아이템 그림 · 정의 · 이름) 를 돌림
4. 빌드하면 탈것 아이템이 생김 (크리에이티브 RPG 장비 탭 · `/mount give <키>`) — 플레이어가 쓰면 그 탈것을 얻고, 스탯 창 탈것 칸 Shift + 누르기로 고름

## 빌드 (GitHub Actions)

`main` 에 올리면 자동으로: Fabric 버전 확인 → 규칙 코어 대조 시험 → 모드 빌드 → 게임 시험 (서버) → 화면 시험 (클라이언트, xvfb — 사진첩 23개를 8묶음으로 동시에) → 모두 통과하면 Releases 의 `latest` 에 jar.
각 단계 로그와 화면 시험 사진은 `ci-logs` 브랜치에 올라갑니다 (`SUMMARY.txt` · `ERRORS.txt` · 단계별 로그 · 묶음마다 `client-checks-<묶음>.txt` · `shots/`).

직접 빌드: JDK 25 + Node 22 가 있는 PC 에서 `./check-core.sh && ./gradlew build` (build 가 서버 게임 시험을 함께 돌림), 화면 시험은 `./gradlew runClientGameTest`.
