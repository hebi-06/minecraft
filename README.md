# MMO RPG — 자바 에디션 (Fabric 모드)

베드락 애드온 **MMO RPG 시스템** (v2.27.0) 을 마인크래프트 **자바 에디션 26.3 (Fabric)** 으로 옮긴 모드입니다 (1.21.1 판은 따로 보관 — 아래 설치).
애드온 (모바일 · 베드락) 은 v2.27.0 에서 개발을 멈췄고, 7단계 (스탯 트리) · 8단계 (룬 돌파) · 9단계 (지역 몬스터 8종 · 긴 퀘스트 · 레벨업 3배) · 10단계 (영웅 무기 스킬) · 11단계 (스킬 칸) · 12단계 (새 무기 넷 · 정령왕 강림) · 13단계 (장식 — 0.13.0) · 14단계 (룬 뽑기 창 · 천장 · 한정 뽑기 — 0.14.0) · 한정 초월 룬 (0.16.0 · 0.17.0 · 0.18.0) 부터는 이 자바 모드에만 기능을 더합니다.
밸런스 수치와 공식은 애드온에서 그대로 가져온 규칙 코어 (`core/`) 를 씁니다 — 애드온 JS 와 같은 입력 28,530개에서 같은 값이 나오는 것을 매 빌드마다 확인합니다.

궁니르와 겹치던 동작 (던져서 돌아옴 · 하늘에서 거대한 무기) 대신 **세계수의 씨앗** (조준한 땅에 빛나는 씨앗 → 가시덤불이 솟아 둘레 적을 찌르고 1.2초 묶음 → 빛의 꽃이 피며 터짐) · **세계수 강림** (뿌리가 땅속으로 달려가 조준한 곳에 거대한 세계수가 솟음 — 둘레 적을 띄우고 묶음 → 금빛 잎이 두 번 쏟아짐 (마법 피해) → 준 피해 15% 회복, 최대 체력 35%). 방패 초월 = **스발린** (해 앞에 서서 세상이 불타지 않게 막는 방패 — 이미르의 얼음 속에서 나옴, 전설 퀘스트 글도) — **서리 돌진** (아이기스의 고르곤 돌진: 메두사의 석화 → 얼음 핵의 서리 숨결 · 빙결) · **일식** (신의 방벽: 금빛 돔 → 얼음빛 돔 + 돔 너머 앞쪽 하늘에 해를 가린 스발린 (화면 위쪽에 보이는 일식 — 접힐 때 다이아몬드 고리), 번개 폭발 → 해가 드러나며 불꽃 폭발 · 드러난 해에서 적마다 햇빛 줄기). 서리 돌진의 얼음 조각은 얼음 결정 그림, 세계수의 도끼 평타는 잎빛 내려찍기 · 금빛 기운. 배율 합 · 재사용 대기 · 회복 · 아이템 ID 는 그대로 (가진 반고의 도끼 · 아이기스의 방패는 새 이름으로 바뀜), 3D 모델은 사용자 디자인이 오기 전까지 지금 것 (빛 알갱이 색만 새 컨셉).

0.12.5 밸런스 (사용자 요청 "룬, 무기, 스킬, 방어구 4가지를 합쳐서 사용했을 때 밸런스 확인" → "갑옷을 추가하자 2개 스탯으로 가는 애들 것을, 방패 너프, 3번도"): 게임 규칙 코어의 수치로 무기 종류마다 레벨별 가장 좋은 세팅 (무기 · 입을 수 있는 갑옷 · 룬 8칸 · 스킬) 의 지속 피해 × 버티는 힘 (EHP) 을 비교한 결과에 따라
- **두 스탯 무기용 갑옷 5종** (`rules_more.json` `ARMOR_TYPES` · `ARMOR_TYPE_ORDER`): 마검 · 창 · 낫 · 전투 망치 · 성스러운 홀은 요구 스탯이 2 : 1 이라 한 스탯 갑옷 (요구가 한 스탯에 몰림) 을 같은 레벨로는 입지 못했음 (40렙 125포인트 < 무기 110 + 갑옷 110 의 겹치지 않는 몫). 무기와 같은 비율의 갑옷 — 마력+힘 · 힘+민첩 · 민첩+마력 · 체력+힘 · 마력+체력 (세트 보너스 두 스탯 0.6씩, 방어는 두 스탯 갑옷 방어의 평균, 모양은 세트 그대로, 아이콘 배지는 두 스탯 색 반반 — `tools/armor_types_more.py`). 갑옷 상점 아랫줄, 칸 설명에 어울리는 무기.
- **방패 상시 피해 감소 상한 40% → 25%** (`SHIELD.passiveCap` — 40렙 종합 지수 2.95 → 2.41, 막기는 그대로).
- **가벼운 갑옷 방어 민첩 0.8 → 0.9 · 마력 0.7 → 0.8** (`ARMOR_TYPES.dex` · `int` `prot` — 근접 민첩 · 마력 무기가 버티는 힘).
- 40렙 종합 지수 (칼 = 1): 단검 0.97 · 도끼 1.24 · 방패 2.41 · 활 0.80 · 완드 0.70 · 마검 0.99 · 창 0.89 · 낫 0.92 · 전투 망치 1.50 · 성스러운 홀 1.25 (전: 0.38 ~ 2.95). 룬 계수는 사용자가 정함 (룬 계수표 — 고친 값을 읽어 넣음).

0.12.6 (사용자 요청 "성기사 체력힘으로 바꾸고 사신의 룬 추가해서 일단 낫 전용 룬" — 고른 것: 5개 일반 ~ 초월 · 모든 뽑기에 섞기 · **피의 초승달** 컨셉):
- **성기사 룬 적용 스탯 체력 → 체력 + 힘 × 0.5** (`rules_more.json` `RUNE_FAMILIES.holy` — 도끼 계열 (힘 + 체력 × 0.5) 과 같은 꼴, 설명 줄 "체력 1.0 + 힘 0.5")
- **사신 계열 (17번째, 낫 전용)**: 적용 스탯 민첩 + 마력 × 0.5 (낫의 요구 스탯과 같은 2 : 1). 낫을 오른손에 든 동안만 쓰임 — 다른 무기 · 맨손이면 스킬 칸 아이콘이 어두운 빨강 + 무기 이름, 눌러도 "… 낫을 들어야 쓸 수 있는 룬입니다" (재사용 대기 없음). 배율 합은 다른 계열과 같음 (4 · 7 · 12 · 20 · 32 — 출혈 포함), 룬 뽑기권 (일반 · 고급) 에서 다른 계열과 같은 확률 (1 / 17 — 스탯 룬 뽑기권은 이름이 같은 계열만이라 나오지 않음)

| 등급 | 룬 | 동작 | 배율 |
|---|---|---|---|
| 일반 | 피의 초승달 | 핏빛 초승달을 날려 일직선 관통 → 출혈 (1초마다 3번) | 2.5 + 출혈 0.5 × 3 |
| 희귀 | 핏빛 수확 | 낫을 두 번 휘둘러 앞쪽 150° 를 벰, 벨 때마다 흡혈 (적마다 최대 체력 2%, 5명까지) | 3.5 × 2 |
| 고귀 | 피의 회오리 | 핏빛 초승달을 두르고 돌며 주위 4칸을 4번 벰 → 출혈 (4번) | 2.4 × 4 + 출혈 0.6 × 4 |
| 영웅 | 피의 낙인 | 앞쪽 적 5명에게 초승달 낙인 (둔화) → 1초 뒤 폭발 + 출혈 + 흡혈 3% | 14 + 출혈 1.5 × 4 |

  - 연출: 핏빛 초승달 (검기 그림을 핏빛으로) · 핏방울 · 붉은 마법진 · 하늘의 붉은 달 (3돌부터는 화면 하늘빛 · 번쩍임도 핏빛 — 광전사의 혼과 같음), 출혈 피해도 피해 숫자로. 룬 아이콘 5장은 애드온 룬과 같은 돌 · 등급 테두리 위에 초승달 + 핏방울 (`tools/rune_family_more.py`)
  - 돌파 (적월 강림): 3돌 달빛 7 → 8.5칸 · 칼날 6 → 7번 · 추락 뒤 출혈 (위력 ×1, 4번), 6돌 추락 위력 ×14 → ×22 · 달빛 8.5 → 10칸 · 칼날 7 → 8번 · 흡혈 5 → 8%

0.12.7 무기 디자인 (사용자 요청 "무기 디자인 리워크 파일 — 각 무기에 적용", 클로드 디자인이 만든 자바 리소스 팩 `weapon_pack` — 10종류 × 5등급 + 티르빙 51개, 32 × 32 텍스처 · 영웅 · 초월은 발광 맥동 애니메이션): 무기 디자인 51개 모두 (같은 디자인을 쓰는 무기 ID 231개) 를 바꿈 (아래 "무기 디자인 바꾸기").

0.12.8 평타 · 스킬 색 (사용자 요청 "스발린이나 세계수의 도끼, 묠리르, 초월 낫 등 각 초월, 영웅 등급 무기 색에 맞춰서 무기 스킬들의 색을 무기에 맞춰줘 + 평타 포함"): 영웅 10종 · 초월 11종의 평타 · 스킬 색을 0.12.7 무기 디자인의 색 (텍스처의 빛나는 점 · 몸통 색 — 손에 든 무기의 빛 알갱이와 같은 계열) 에 맞춤. 스킬 이름 · 설명 · 수치 · 동작 · 크기는 그대로.

## 설치

1. [Fabric Loader](https://fabricmc.net/use/) (0.19.5 이상) 를 마인크래프트 **26.3** 에 설치
2. [Fabric API](https://modrinth.com/mod/fabric-api) (26.3 용, 0.162.0 이상) 와 이 모드 jar 를 `mods` 폴더에
3. 모드 jar: 이 저장소의 **Releases → latest** (main 에 올릴 때마다 모든 시험을 통과하면 자동으로 새로 만들어짐)

마인크래프트 **1.21.1** 용 (1단계까지, 더 고치지 않음): **Releases → release-mc-1.21.1** (`mc-1.21.1` 브랜치, Fabric API 0.116.x+1.21.1).

서버에서 쓰려면 서버와 클라이언트 모두에 넣어야 합니다 (창 · 갑옷 입은 모습 · 장식 · 체력 바 · 길 안내 · 몬스터 · 보스 · 탈것은 클라이언트의 모드가 그림).

## 스탯 트리 고치기

스탯 트리는 데이터로 정합니다 (`core/src/main/resources/mmorpg/stat_tree.json` — 고친 뒤 빌드):

- `trees.<스탯>.nodes`: 칸 목록 (at 이 커지는 순서). 칸 하나 = `at` (열리는 스탯 값) · `name` · `bonus` (예: `{"atk": 2}`) · `reward` (예: `{"stat": 1, "rune": 1, "adv": 1}`), 갈래 칸은 `pick` (두 가지 `{name, bonus}` — 갈래 칸에는 reward 를 두지 않음: 초기화하고 다시 골라 보상을 두 번 받지 않게)
- 보너스 종류 (`kinds`): `atk` 공격력 % · `rune` 룬 피해 % · `crit` 치명타 확률 %p · `critDmg` 치명타 피해 % (배율에 더함) · `hp` 최대 체력 · `def` 받는 피해 % 감소 · `speed` 이동 속도 % · `cdr` 재사용 대기 % 감소 — 이름 · 칸 그림 (`icon` 아이템) 도 여기서
- `caps`: 나무 넷을 더한 합의 상한, `reset.perPick`: 갈래 하나를 지우는 실버 (0.21.0 전에는 에메랄드)
- `tickets`: 스탯 룬 뽑기권 (아이템 ID · 이름 · 나오는 계열). 뽑기권을 더하면 `python3 tools/stat_tickets.py` 로 그림 · 모델을 만듦
- 칸을 늘리면 창은 칸 수에 맞춰 그림 (한 줄에 10칸 기준 — 더 많으면 창이 넓어져야 함). `./check-core.sh` 가 파일 모양 (칸 · 갈래 · 보상 이름) 을 확인

## 룬 돌파 고치기

룬 돌파는 데이터로 정합니다 (`core/src/main/resources/mmorpg/rune_break.json` — 고친 뒤 빌드):

- `max` (가장 높은 단계 6) · `perLevel` (1돌마다 계수 0.1 = +10%) · `scaleKeys` (계수를 곱하는 룬 정의 값 — 회복 `heal` · 보호막 `shield`, 피해는 위력 P 에 곱함) · `grindPerLevel` (갈 때 1돌마다 룬 하나 값)
- `tiers` (초월 룬이 바뀌는 단계 3 · 6) · `fx.<단계>` (연출: 하늘빛 시간 배율 `skyTicks` · 거리 배율 `skyDist` (작을수록 짙음) · 번쩍임 더 머묾 `flashHold` 초 · 걷힘 배율 `flashOut` · 화면 테두리 빛 `edge` 0~1 · 금빛 각성 `awaken`)
- `transcend.<룬 효과>.extra` (초월 룬 하나에 하나, 없어도 됨): `type` `echo` = `at` 돌부터 룬이 나가고 `after` 틱 뒤 그 룬 효과가 한 번 더 (지금 겨눈 곳 · 위력 × `mult`, 룬 정의에 `set` 을 덮음 — 예고를 짧게), `text` 의 `{mult}` = mult × 100
- `transcend.<룬 효과>.<단계>`: 바뀌는 값 목록 — `key` (룬 정의의 값 이름, rules.json `RUNES.<계열>.transcend` — 없는 값을 새로 붙이면 `base` 에 원래 값, 예: 기절 `stun` 0 · 연쇄 수 `chainCount` 1) · `to` (바뀐 값) · `div` (글자에 보일 때 나누는 수 — 틱 → 초 20, 비율 → % 0.01) · `text` (설명 줄 — `{from}` · `{to}` 는 앞 단계 값 · 바뀐 값). 6돌은 3돌 값에서 이어짐
- `./check-core.sh` 가 모양을 확인 (초월 17종 모두 3 · 6돌 · 값이 룬 정의에 있고 커지는지 · 글자). 단계 수를 바꾸면 `python3 tools/rune_break_badges.py` 로 배지를 다시 만듦

## 무기 디자인 바꾸기

0.12.7 부터 무기 디자인 51개는 모두 사용자 리워크 (자바 아이템 모델 — `tools/weapon_art/<디자인>.java.json` · `.java.png` (+ `.java.png.mcmeta`)) 입니다. 이 파일이 있으면 그 디자인은 자바 모델을 쓰고 (`geo_tex.load_java`), 손 자세 (뼈대 · 1인칭 값) 와 지금 빛 알갱이 자리만 `<디자인>.geo.json` · `designs.json` 에서 가져옵니다. `.java.json` 을 지우면 예전 디자인 (베드락 `.geo.json`) 으로 돌아감.

자바 리소스 팩 (클로드 디자인 · Blockbench 자바 아이템 모델) 으로 바꾸기:
1. `python3 tools/weapon_pack_import.py <weapon_pack.zip 또는 폴더>` — `assets/weapons/models/item/<디자인>.json` · `textures/item/<디자인>.png` (+ `.png.mcmeta`) 를 디자인 이름 (`designs.json` 의 51개 — 예: `scythe_transcend_lv0` = 크로노스의 낫, 완드는 `staff_*`) 대로 가져와 자리 맞춤 (`mmorpg`: `anchor` 팩 좌표의 손 자리 = `grip` (방패 `handle`) 상자 가운데 → `to` 지금 손 자리, `scale` = 지금 디자인과 같은 y · z 대각선 길이) 을 적고, 가방 아이콘 (`<디자인>.icon.png` · `textures/item/<종류>/<무기 ID>.png`) 을 다시 그림. 팩에 없는 디자인은 그대로. 받는 모양: 상자 모델 (parent 없음) · 텍스처 한 장 (`#0`) · 상자 회전 한 축 22.5° 단위 · ±45° · 상자는 -16 ~ 32 · 면 rotation 0 · 90 · 180 · 270 (어기면 멈추고 알림)
2. 크기를 바꾸려면 그 디자인의 `.java.json` 에서 `mmorpg.scale` 만 고침 (손 자리는 `anchor` · `to`). 아이콘만 다시: `python3 tools/weapon_pack_import.py --icons`

4. 영웅 · 초월 디자인의 색이 바뀌면 평타 · 스킬 색도 (0.12.8): `rules_more.json` 의 `SLASH.<무기 모양>` (`LOOK.<종류>_<등급>.slash` — 빛 `glow` · 심지 `core` · 기운 `aura` · 치명타 `crit` / `critColor`) · `HERO_SKILLS.<종류>.color` · `SKILLS.<종류>[].color` (애드온 7종 초월은 `SKILLS.color`) · 스킬 코드의 고정 색 (예: `Yggdrasil.LEAF` · `Aegis.FLAME`). 스발린 빛의 방패 그림은 `python3 tools/java_fx_art.py` 가 스발린 모델 (`shield_transcend_lv0.java.*`) 앞모습에서 다시 그림 (문장 보석 자리 = `Aegis.AE_EYES` — 스크립트의 `svalinn_eye()`)

## 장식 바꾸기 · 더하기

장식은 데이터로 정합니다 — `src/main/resources/mmorpg/cosmetics.json` (서버 · 클라이언트 · 그림 도구가 같이 읽음):

- `slots`: 칸 이름 (`weapon` · `helmet` · `chest` · `legs` · `boots` · `head` · `back` · `aura` · `title` — `hide` 는 갑옷 칸만 true)
- `items.<키>`: `slot` · `name` · `price` (골드 — 0.21.0, 예전 에메랄드 값의 1/10) · `desc` (설명 줄) · `color` (목록 · 연출 색). 칸마다 더: 무기 = `weapon` (무기 종류) + `design` (무기 디자인 — 이름은 `<종류>_skin_<이름>`, 완드는 `staff_skin_…`: 1인칭 세워 들기 · 아이콘 방향이 이름 앞으로 정해짐), 갑옷 · 머리 · 등 = `model` (+ 갑옷은 `set`, `translucent: true` 면 그림의 알파대로 반투명 — 0.14.2), 등 = `dust` (가루 — `rate` 초당 수 (움직이면 최대 2.5배) · `colors` · `style` sparkle (떨어지는 반짝임 — 기본) / ember (피어오르는 불티 — 0.15.0), 0.14.2), 오라 = `aura` (`kind` embers · orbit · frost · petals · lightning · hearts · shadow (뒤 넷은 0.15.0 — shadow 의 마지막 색은 불티), `rate` 초당 수, `colors`), 칭호 = `title` (§ 색 코드 글)
- 키는 플레이어 기록 · 명령어 · 아이템 모델 (`rpg:cosmetic_<키>`) 에 쓰이므로 이미 판 장식은 키를 바꾸지 않음 (지우면 가진 사람의 기록에서 빠짐)

탈것은 데이터로 정합니다 (코드를 고치지 않음):

1. 애드온 행동 팩에 탈것 엔티티 (`RPG_BP/entities/rpg_mounts/<이름>.json` — `minecraft:rideable` 자리 · `movement` 빠르기 · `horse.jump_strength` 뛰는 힘 · `variable_max_auto_step` 오르는 높이 · `collision_box` · 피해 면역, 다이어울프와 같은 모양) 과 리소스 팩 (모델 · 동작 · 렌더 컨트롤러 `render_controllers/rpg_mounts/` · 텍스처) 을 넣음
2. `src/main/resources/mmorpg/mounts.json` 의 `mounts` 에 한 항목: `name` (이름) · `entity` (엔티티 ID) · `item` (탈것 아이템 ID, `rpg:mount_<키>`) · `starter` (처음부터 가짐) · `color` (연출 색) · `particle` (흩날리는 파티클) · `portrait` (아이템 그림 바탕) · `sounds` (부를 때 · 사라질 때) · `desc` (아이템 설명) · `seatLift` (탄 사람 높이 보정, 없으면 0.13)
3. `python3 tools/bedrock_entities.py <애드온 폴더>` (엔티티 수치 · 모델 · 텍스처) 와 `python3 tools/mount_items.py` (아이템 그림 · 정의 · 이름) 를 돌림
4. 빌드하면 탈것 아이템이 생김 (크리에이티브 RPG 장비 탭 · `/mount give <키>`) — 플레이어가 쓰면 그 탈것을 얻고, 스탯 창 탈것 칸 Shift + 누르기로 고름

## 빌드 (GitHub Actions)

`main` 에 올리면 자동으로: Fabric 버전 확인 → 규칙 코어 대조 시험 → 모드 빌드 → 게임 시험 (서버) → 화면 시험 (클라이언트, xvfb — 사진첩 30개를 10묶음으로 동시에) → 모두 통과하면 Releases 의 `latest` 에 jar.
각 단계 로그와 화면 시험 사진은 `ci-logs` 브랜치에 올라갑니다 (`SUMMARY.txt` · `ERRORS.txt` · 단계별 로그 · 묶음마다 `client-checks-<묶음>.txt` · `shots/`). 빌드 · 게임 시험 로그는 `ci-logs-build` 브랜치에도 (build 일이 바로 올림).

직접 빌드: JDK 25 + Node 22 가 있는 PC 에서 `./check-core.sh && ./gradlew build` (build 가 서버 게임 시험을 함께 돌림), 화면 시험은 `./gradlew runClientGameTest`.
